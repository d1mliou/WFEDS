## 1. RECOMMENDED JSON SCHEMA

### 1.1 The decision between the two candidates

**Recommended: MINIMAL-5 as the base, extended with `initial_state` grafted back from Validation.md section 3f and from Candidate A. Name: `wfeds_final_answer`. Six root keys.**

Candidate A (mirror-the-payload) lost on three measured grounds, not on taste. First, it mandates two ISO timestamp slots (`inputs.start_time_utc`, `final_hour.time_utc`), and `score_numeric_traceability` (scripts/validation/agent_eval.py:308-341) flags the minute component of an echoed timestamp whenever it exceeds `max_ordinal=48`, because `numbers_in_result` (agent_eval.py:288-305) cannot parse an ISO string through `norm_num` and so contributes nothing to the allowed set; measured on all 192 in-scope stored compacts, an ideal Candidate A answer scores numeric_ok 158/192 against the 2026-09-01 run's 195/195, a pure harness penalty the free-text arm never faced (0 of 195 stored 2026-09-01 Stage-C replies contain an ISO timestamp). Second, once the mandatory text-surface rule of section 3 is applied, both candidates score identically on every shared criterion (192/192), so Candidate A's 27 factual leaves, up to 91 copied numbers for A03, buy nothing in the comparison while adding truncation risk that neither provider's strict mode can catch (no `minItems`). Third, Candidate A's `scenario_setup` block mirrors the model's own tool arguments, which `score_stage_a` (agent_eval.py:251-272) already scores, so it silently imports Stage A into the Stage-C gate and double-counts it. What was grafted from Candidate A: the four-value `status` enum with explicit Greek semantics; the `additionalProperties: false` discipline on every object, which is what makes fabricated geography structurally impossible inside the factual block; the verbatim reuse of `agent.py::_compact` field_meanings glosses (agent.py:221-230) as slot descriptions, so the schema adds no *semantic* information the free arms do not also receive in every tool payload (it does add instruction text, see 1.5); and `initial_state`, which MINIMAL-5 had refused. `initial_state` is restored for two reasons: Validation.md:1328-1333 names it as one of four frozen slot names, and keeping it avoids leaving two competing schemas in the vault; and period 0 already carries `cut_off=6` in every in-scope fixture, so the documented "h0 read as the first hour" failure (rubric rule R2/R7) is targeted directly at a cost of two integers.

Total mandated integers per answer: 2 (`initial_state`) + 2 x |critical events| + 3 (`final_state`). Measured over the 13 cases from the stored luna payloads, |critical events| is 3 (B02) to 8 (A03), so 11 to 21 integers. Candidate A mandated 53 to 116 values.

Note on the 192 denominator in the first paragraph: it is the in-scope rows that carry a parsed tool payload, that is 195 rows minus the 3 zero-tool-call rows (A02#4, A02#5, A03#4), and it is the correct denominator for a simulation that needs a compact payload. The 191 narrated figure used elsewhere additionally excludes I03#4, whose 503 left a payload but no reply. Both denominators were re-derived independently on 2026-09-21 and both are correct in their own place.

### 1.2 The schema (complete, final)

The full `response_format` object lives at `scripts/validation/wfeds_final_answer_schema.json`, **revised by REVISION 3 in exactly one description string, `interpretation.description` (file line 79); the other twelve descriptions and the whole structural skeleton are byte-unchanged. Revision 5 changes nothing in this file.** `sha256(json.dumps(inner_schema, ensure_ascii=False, sort_keys=True))` = `d079a01b22d4c344a4f2b7a6a62b147215860deeeddd373e5b597f8ed498ccf0`, prefix **`d079a01b22d4`**, recomputed 2026-09-21 from the file as written; the superseded value was `d7aa3cf7a148`. **The schema is FROZEN by revision 5 and was not edited after the pilot.** `FINAL_ANSWER_SCHEMA_SHA256` stays `d079a01b22d4c344a4f2b7a6a62b147215860deeeddd373e5b597f8ed498ccf0`, prefix `d079a01b22d4`; **no `description` string was touched after the 2026-09-21 pilot**, neither to shorten the Greek text that 5.6 shows is the dominant cost term nor to tighten the `critical_transitions` wording that 5.8.8 shows one model over-filled. Both of those are costing and reporting findings, and neither is a licence to edit the artefact under test mid-experiment. The serialised inner schema is 3,998 characters and 5,643 UTF-8 bytes, and the file on disk is 6,812 bytes over the same 88 CRLF lines. Structure:

- Root object, `additionalProperties: false`, `required` lists all six properties.
- `status`: string enum `["ok","tool_error","insufficient_input","abstained"]`.
- `initial_state`: array of `{period: integer, settlements_without_route: integer}`.
- `critical_transitions`: array of `{period: integer, settlements_without_route: integer}`.
- `final_state`: array of `{period: integer, settlements_without_route: integer, road_segments_removed: integer}`.
- `interpretation`: string, free Greek.
- `limitations`: string, free Greek.

Design rules that are load-bearing and must not be relaxed:

1. **No nulls, no `anyOf`, no `oneOf`, no `$ref`, no `const`, no `minItems`/`maxItems`, no `pattern`, no `format`, no `minimum`.** Optionality for the non-`ok` statuses is expressed as an empty array. This is the single most portable construct available and it is why MINIMAL-5 was preferred as the base.
2. **Exactly four integer field names in the whole factual block**, all glossed from field_meanings. There is no string-typed factual leaf anywhere, so no settlement name, road name, direction, wind, terrain, front geometry, inter-front distance, per-settlement population or per-settlement exit can be written into it. System-prompt rule 6 (agent.py:79-85) is enforced structurally in the factual block rather than by instruction.
3. **The intervention is a structured-output contract, and it carries instruction text on two surfaces, both inside the `response_format` object.** Measured on the schema as revised (tiktoken `o200k_base`, `json.dumps(..., ensure_ascii=False)` with the file's key order): the object is **1,275 tokens**, of which **885 tokens, 69 percent, are the 13 Greek `description` strings** (2,563 characters), and **323 tokens** are the structural skeleton with every description deleted. State the serialisation with the figure, because the hash is defined on a different one: under `sort_keys=True`, the form that is hashed, the same object is 1,264 tokens. **These are `ensure_ascii=False` counts and they are NOT what the provider bills.** Measured on all four successful pilot calls, the object costs **6,659 prompt tokens** per structured call, a factor of 5.22, because the request body travels backslash-u escaped and each Greek character of the 13 descriptions becomes a six-character `\uXXXX` sequence; see 5.6 and 5.8.6. Every token and dollar figure in this document is computed on 6,659 and not on 1,275. **`SYSTEM_PROMPT_SHA256[:12] = f005ab5e76d6` in both arms**, byte-identical, and there is no structured prompt variant; `TOOLS_SCHEMA_SHA256[:12]` stays `0c5ae805199e` in every arm. The stored baseline was produced on the same string, which is verified and not assumed: Phase 0a records that the working-tree `SYSTEM_PROMPT` hashes to `f005ab5e76d6` and matches all three stored runs. **The identical prompt hash is not evidence of a single-variable intervention either, and must never be cited as such:** 885 of the 1,275 tokens are Greek instruction the free arms never received. The complete surface-by-surface list of what differs and what is held identical is section 4.5.
4. **Slot names restate the Greek gloss the free arms also receive.** `settlements_without_route` is an English restatement of `cut_off` = "ΟΙΚΙΣΜΟΙ χωρίς καμία διαδρομή διαφυγής (ΟΧΙ δρόμοι)" (agent.py:222); `road_segments_removed` restates `edges_removed` = "ΟΔΙΚΑ ΤΜΗΜΑΤΑ που αφαιρέθηκαν - ΜΟΝΟ τελική ώρα" (agent.py:227). No new semantics. `period` is deliberately left unglossed beyond "the payload's `period`, verbatim", because the free arms are never told that period 0 is the initial state, and glossing it would hand the structured arm information on precisely the axis being measured.
5. **The contract is coherent with itself, and the repair is made inside the contract.** Free-arm rule 7 (agent.py:86-89) orders the model not to restate the cards' numbers and caps the reply at two to four bullets, while the schema mandates 11 to 21 of exactly those numbers and removes the bullet container; the schema's own `interpretation.description` re-imported that rule with "Ισχύουν ΟΛΟΙ οι κανόνες του συστήματος, χωρίς εξαίρεση", so the contract as first drafted contradicted itself inside one artefact. The repair is made in `interpretation.description`, which scopes rule 7's number prohibition and its two-to-four-bullet cap to that field by name and assigns the number-carrying duty to the mandatory slots when `status` is "ok". The prohibition, the interpretive focus and the cap all survive verbatim in the prompt, in both arms. **`SYSTEM_PROMPT` is not edited and is byte-identical in both arms** (`f005ab5e76d6`), so round 1 is identical across arms by construction and Stage A and Stage B cannot be moved by the treatment (4.5, 5.4). The schema JSON **is** edited, on one line, and `FINAL_ANSWER_SCHEMA_SHA256` is re-frozen from `d7aa3cf7a148` to `d079a01b22d4`. See 1.5.

Reporting one rate would let a provider-mechanism difference and a model-fidelity difference cancel inside a single number.

### 1.5 The structured-output contract: what the treatment actually is

This subsection replaces the revision-1 position that the intervention "carries no prompt text" and is therefore "a single variable at the API level". That position was false in fact and unsafe in practice. It was false because 885 of the 1,275 tokens of the `response_format` object as revised, and 783 of 1,173 as first drafted, are Greek natural-language instruction that the free arm never received in any form, including behavioural directives (the empty-array rule for non-`ok` statuses, the "put the verbatim error message in `interpretation`" rule, the "ΟΧΙ από την τελευταία γραμμή του change_hours" warning in `final_state`). It was unsafe because freezing `SYSTEM_PROMPT` bytes froze the *hash*, not the *behaviour*: it shipped an instruction set the model could not satisfy, and left each model to pick silently which instruction to discard.

**The contradiction, stated precisely.** Free-arm rule 7, agent.py:86-89, verbatim:

```
7. Μετά από κάθε τρέξιμο, ο χρήστης βλέπει ΗΔΗ δύο δομημένες κάρτες (παράμετροι
   + αριθμητικά αποτελέσματα). ΜΗΝ επαναλαμβάνεις τα ίδια νούμερα σε λίστα -
   εστίασε στην ΕΡΜΗΝΕΙΑ: το χρονικό της εξέλιξης (πότε αλλάζει κάτι), τι
   σημαίνει για αποφάσεις, και τα προτεινόμενα μέτρα, σε 2-4 σύντομα bullets.
```

Under the contract this is unsatisfiable in three independent ways at once. (i) The prohibition is inverted: a JSON array of `{period, settlements_without_route}` pairs is a list of exactly the numbers the analyst already has on the two cards. (ii) The container is gone: the reply is a six-key object and nothing bounds `interpretation`, so "σε 2-4 σύντομα bullets" names a shape that no longer exists. (iii) The schema contradicts itself, not merely the prompt: `interpretation.description` ends "Ισχύουν ΟΛΟΙ οι κανόνες του συστήματος, χωρίς εξαίρεση", which imports rule 7 verbatim into the artefact whose sibling arrays violate it.

**Why this is a confound and not a nuisance.** The model must pick a loser, and all three resolutions damage the experiment. ### 2.4 Contract outcomes, judgeable surface, and records with no judged surface

**The nine contract outcomes**, mutually exclusive, assigned by first match in this precedence order, recorded on every raw row as `contract_outcome` in both arms. **Outcomes 1 to 4 are arm-neutral and are evaluated on every arm. Outcomes 5 to 8 are contract-specific and are evaluated only when `output_contract == "structured"`. 1. `runtime_error`. `row["error"]` is set. Provider or harness exception, not a model output.

- A record with no judgeable surface is **EXCLUDED** from the per-criterion denominators of C1a and C4, with the excluded count printed beside every such cell. Reason: both return a mechanical artefact on an empty string rather than information about the model. Verified by running the repository functions: `score_numeric_traceability("", compact)` returns `(True, [])`, a vacuous pass; `is_greek("")` is False and `has_limits_statement("")` is False, so `score_policies` returns exactly the two problems "not Greek" and "no limits statement". The row still fails C5-common through the no-surface rule and through `deterministic_pass`; only the published per-criterion cells are cleaned. This is not a new convention: section 3.2 already performs this correction by hand for gemini (9 policy-problem rows minus the 4 empty-503 rows leaves 5 genuine failures). The rule makes an existing manual correction systematic and arm-neutral instead of one-sided.
- **C5-common contains no schema term of any kind.** Schema validity and contract validity are never components of it and never columns of the comparison table. The complete structured-system pass (SSP) that does contain them is defined in 3.1 and is intervention-only.

**Stated affirmatively, because this is the consequence that surprises.** A `schema_invalid` or `validator_invalid` record that still has a judgeable surface is scored on C5-common exactly as a free-arm record is: its narrative surface is rendered, its claims are judged, its numbers and policies are checked, and **it can PASS C5-common while failing SSP**. That is deliberate, and it is what makes C5-common a fair comparison quantity: a model that writes a good Greek narration and a malformed envelope is not penalised twice on the channel the comparison measures. The envelope failure is carried entirely by SSP, by `json_schema_validity_rate` and by `contract_validity_rate`, all three of which are intervention-only. The only route by which a contract failure touches C5-common is the loss of the surface itself (no parse, no `interpretation` string, under 120 characters), which is the partial insulation the Residual paragraph below bounds and which the salvage variant V3 of 3.3 prices.

**Which outcomes keep a judgeable surface.** `valid` and `validator_invalid` always do, because schema conformance guarantees both strings exist. `schema_invalid` does when `interpretation` is present and is a string, which is the common case for an extra root key, a wrong leaf type or an unknown status value; it does not when `interpretation` is missing or is not a string. `runtime_error`, `round_ceiling`, `contract_not_attached`, `no_final_message` and `not_json` (truncated) never do. `not_json` (Greek prose) is the one pre-declared **choice** rather than a fact: under the primary variant it has no surface, because defining the structured arm's surface as "the parsed `interpretation`, or the whole reply when parsing fails" would give the structured arm two chances, obey the contract and be judged on a narrow self-selected surface or ignore it and be judged exactly as a free arm, which is a best-of-both rule and is not arm-neutral. Variant V3 of 3.3 publishes the cost of that choice as a number instead of burying it. **This paragraph governs the structured arm only.** On a free arm the judgeable-surface test never consults `contract_outcome`: it is exactly (`row["error"]` falsy) AND (a compact payload parsed from that row's own `tool_outputs`) AND (`len(reply.strip()) >= 120`). `free_text` therefore keeps a judgeable surface whenever those three hold; outcomes 1 to 4 never do, on either arm. Edits C2 and C3 must test the surface predicate, never the outcome value, and `contract_outcome` appears in `c_source` and `coverage_source` only as the recorded **reason**.

**Symmetry with the free arms, argued rather than asserted.** The free arms' nearest counterpart to an unusable output is outcomes 1 to 4, and the existing code already treats them as hard failures rather than pending: axis3_full_system.py:178-181 forces `stage_c = False` with `c_source = "runtime_error"` **ahead of** the human-override branch, and `deterministic_pass` (:64-76) returns False on the same condition. Verified on the frozen run: gemini has 4 such rows in scope (A02#4, A02#5, A03#4, I03#4), all with `reply == ""`, all excluded from both label passes (61 labelled records against 65 rows), all scored FAIL; luna and terra have zero. Verified further that no stored in-scope reply is short: minimum length 982 characters for gemini, 984 for luna, 920 for terra, so the 120-character floor is inert on the stored 2026-09-01 replies and cannot penalise them retroactively. The no-surface rule therefore does not import a new standard into a free arm; it states in arm-neutral language the standard the free arm already meets, so the structured arm meets the same one.

**Residual, to be stated in the document and in the thesis.** C5-common is insulated from schema validity as a *criterion*, but it is not fully insulated from the contract, because a parse failure removes the surface and a missing surface fails the gate. The insulation is partial by construction; the per-outcome counts of 3.3 make the size of the residual visible and variant V3 bounds it.

### 2.6 The boundary rule: four tests in strict precedence

- **T1 invented subject.** The claim asserts or presupposes an entity or attribute the tool never returns: settlement names, road names, spread directions, winds, terrain or fuels, front geometry (head, flanks, perimeter), distances, per-settlement population or exits, per-settlement identity, a per-hour road or network quantity, a fire path, an external interface. Result NOT_IN_RESULT. Hedging does not rescue an invented subject. T1 outranks T3.
- **T2 conflict.** A value, field identity, hour, trend or rate the rows contradict. Result CONTRADICTED.
- **T3 permitted judgement.** A recommendation, priority ordering, timing judgement or caution that (a) names no entity outside the payload, (b) is grounded in at least one named payload value or an ordering derivable from it, and (c) sits in a record carrying a limits statement. Result ADVISORY_INFERENCE.
- **T4 the rest.** Limits framing gives LIMITATION_STATEMENT; a correct restatement gives SUPPORTED.

### 2.7 Tie-breaks R1 to R8 (this is what v2 adds)

- **R1 range attribution.** A delta or state attached to a stated hour range is judged against the whole range. Holds only for a sub-hour, CONTRADICTED.
- **R2 onset against h0.** "αρχίζει από την Xη ώρα" is judged against period 0. If the quantity is already non-zero at period 0, an onset at X > 0 is CONTRADICTED. A claim about the increase beginning at X is judged on the delta.
- **R3 settlement-action vs road-object.** Grammatical object = settlements tracks `cut_off` and is SUPPORTED when the timing is right. Grammatical object = routes/roads/network asserts a road quantity: CONTRADICTED when a value or an hourly trend is attached, NOT_IN_RESULT when no payload value is attached. `edges_removed` is the sole road quantity and exists only for the final hour.
- **R4 class-4 gloss.** Renaming class 4 as very high intensity / extreme / hard to fight, scoped to the FINAL front, is SUPPORTED. Adding a fire type (crown fire, πυρκαγιά κόμης) is NOT_IN_RESULT. Extending 96% to the whole period is CONTRADICTED.
- **R5 weather provenance.** Asserting forecast when `weather_source == "archive"`, or the reverse, is CONTRADICTED. One named field.
- **R6 spatial anchors in advice.** Generic tactics with no named place are ADVISORY_INFERENCE; the same sentence with "μπροστά από την πορεία" or "περιμετρικά του τελικού μετώπου" is NOT_IN_RESULT.
- **R7 hour numbering.** Period p is "ώρα p"; period 0 is "έναρξη" or "ώρα 0", never "1η ώρα". Mapping h0 to the first hour is CONTRADICTED.
- **R8 no double counting of a missing limits statement.** Without a limits statement a recommendation cannot be ADVISORY_INFERENCE, but it does not become negative by that fact alone: SUPPORTED if it asserts nothing beyond the payload, NOT_IN_RESULT if it does. The missing statement is caught once, by C4.

### 2.10 Judge calibration against the frozen 2026-09-01 verdict (mandatory, before any structured judging is trusted)

The frozen human adjudication stays authoritative for the as-published 2026-09-01 run and is never overwritten. The four frozen directories are read-only.

**What the reference standard actually is, stated before any threshold is set.** The `stage_c` column of `axis3_full_system_records.csv` is **not** a human-labelled column. It is the intersection of two independent Claude Opus passes, human-confirmed on its negative cells only. Verified on the frozen file: `stage_c` equals (`stage_c_pass1` AND `stage_c_pass2`) on all 191 labelled rows with **zero** mismatches, and all 65 `human_audit` decisions were FAIL (gemini 44, luna 9, terra 12), so every human decision confirmed what the two-pass intersection already said and the human contributed **zero bits of disagreement**. There is no human-labelled clean cell anywhere in this project. Correction 1 asks for calibration against the human labels; correction 5 budgets zero new human labels. With the labels that exist on disk those two requirements cannot both be met in full, and this subsection says so plainly rather than letting a section title imply an anchoring the data does not support. A genuinely human-anchored kappa would need a fresh stratified human pass that includes clean rows; at 5.7's own rate of about 6 minutes per decision a 60-row stratified pass is about 6 hours, and it is **not funded here**. What is funded is three criteria, two of which measure agreement with an instrument and one of which is genuinely human-anchored.

Revision 1 additionally required that the model ranking luna > terra > gemini be preserved. That requirement is **deleted here and in D-decisions**, and it was wrong on principle, not merely too strict: it presumes the conclusion, and it would select a judge for reproducing the 2026-09-01 result rather than for agreeing with human judgement. A judge that disagreed with the humans but happened to reorder the models would have passed; a judge that matched the humans closely but compressed two models to a tie would have failed. Ranking is an output of the experiment, never an admission criterion for its instrument. No criterion anywhere in 2.10 refers to the ordering of the three models.

**The composition of the calibration set under the two-model design, decided here and recorded with its rejected alternative.** The follow-up's intervention arm is `gpt-5.6-luna` and `gpt-5.6-terra` only (5.8.4), so a reasonable reader will ask why the stored gemini rows are still judged at all. **Decision: they are kept.** The 61 stored narrated gemini rows enter the rubric-v2 pass of this subsection under the run id `gemini_free` with the explicit status **calibration-only**: they are recorded in the run-id table of section 5 as calibration-only, they are **excluded by construction from every comparison cell, every pass^k table and every figure in the results**, and they produce no comparison quantity of any kind. The incremental price is **6 judge calls, 61 record-labellings, about 2.8 to 8.3 USD and zero new human decisions**, because those rows already carry the frozen 2026-09-21 verdicts and S2c is scored against labels that already exist.

The reason is that S2c is the only genuinely human-anchored admission test in this subsection and its reference standard is the frozen set of 65 human FAIL decisions, of which **44 sit on gemini rows**. Drop them and S2c rests on 21 rows (luna 9, terra 12): the pre-declared floor of 60 of 65 is 92.3 percent recall, the proportional equivalent on 21 rows is 20 of 21, so a single missed row fails the gate, and the standard error of a 0.95 recall estimate over 21 Bernoulli trials is about 4.8 points. That is not a criterion, it is a coin flip with a threshold drawn on it. S2a degrades the same way: a pooled kappa over luna plus terra alone would rest on a 16.2 percent negative marginal (21 of 130) instead of 34.0 percent (65 of 191), and kappa is least stable exactly where one cell is thin. S2b is unaffected either way.

**The case against, stated fairly rather than waved away.** Calibrating on rows from a model that is not in the experiment imports a difficulty distribution that does not match the comparison set: 44 of gemini's 61 labelled rows are FAIL, 72 percent, against 14 percent for luna and 18 percent for terra. A judge that clears gemini's blatant negatives can still be mis-calibrated on the marginal luna and terra rows that actually decide the outcome, so a good pooled kappa carried by gemini's easy cells would be reassurance the experiment has not earned. There is also an optics risk: a reader may take gemini's continued presence in the calibration set as a back door into a comparison it was removed from.

**Four conditions that travel with the decision, all pre-declared here.** (1) The 61 rows carry the run id `gemini_free` with the status calibration-only, recorded in the run-id table and excluded by construction from every comparison cell. (2) S2a is reported per model as this subsection already requires, and it is declared **now** that **the luna and terra per-model kappas are the operative figures** while the pooled and gemini figures are context; a pass that depends on gemini's cells alone is reported as such. (3) The S2c floor stays at **60 of 65 pooled**, unchanged, because the 65-row reference standard is unchanged. (4) **No kappa subsample is drawn on `gemini_free`**, because it yields no comparison cell; that saves 19 labellings and 2 calls and costs only a self-consistency figure on a run nobody quotes.

**The rejected alternative, recorded so the trade is auditable.** Dropping the gemini rows from the calibration would bring the judge budget to 32 calls and 340 labellings, 15 to 46 USD, a saving of 6 calls, 61 labellings and 2.8 to 8.3 USD (5.0, 5.7). It is declined. Had it been taken, this document would have had to say plainly that S2c is anchored on 21 human decisions, drop the 60-of-65 floor in favour of a descriptive recall figure with no gate, and record in section 6 that the judge was admitted on instrument agreement with essentially no human anchor. That is a real methodological loss for about 3 to 8 USD.

**One sentence that must not be separated from this decision:** retaining these rows is a decision about the **judge** and has no bearing whatever on the exclusion of `gemini/gemini-2.5-pro` from the experiment, which is the access fact recorded in 5.8.4 and in B16.

**S1.** The new judge, one pass, labels the 191 narrated records of the stored 2026-09-01 run under rubric v2, blind. **Under the single-arm design this pass is not a separate expenditure: it IS the baseline arm's gating pass.** The baseline arm is those same 191 narrated records, its gating pass is one blind rubric-v2 pass over them, and S1 is one blind rubric-v2 pass over them, so the two are the same object and are bought once. That double duty is exactly the economy the retired concurrent control arm destroyed, and 5.0 recomputes the judge accounting on it.

**S2a, instrument agreement, honestly named.** Record-level agreement between the new single v2 pass and the frozen verdict over those 191 records; the 4 `runtime_error` rows carry no labels and are excluded. This quantity is **agreement with the 2026-09-01 instrument**, and it must be captioned in those words wherever it is printed, never as agreement with a human. Pre-declared thresholds, both of which must hold: pooled Cohen's kappa >= 0.61; per-model Cohen's kappa >= 0.50. **Under the two-model design the operative per-model figures are luna and terra**; the pooled figure and gemini's own kappa are context, and a pass carried by gemini's cells alone is reported as such (see the calibration-composition decision above). Justification of the floors, unchanged: the existing instrument's own inter-pass agreement is 0.582 / 0.775 / 0.614, so a per-model floor of 0.50 sits below the observed minimum and does not demand a judge better than the instrument it must match.

**S2b, clean-rate comparability, computed like against like.** Revision 2's third threshold compared a **single** v2 pass against a **two-pass intersection** and was therefore pre-loaded to fail for a reason that has nothing to do with judgement quality. Recomputed on the frozen file over labelled rows: gemini two-pass clean 17/61 = 27.9 percent against pass-1 alone 24/61 = 39.3 percent (**+11.5 points**) and pass-2 alone 22/61 = 36.1 percent (+8.2 points); luna 56/65 = 86.2 against 59/65 = 90.8 (+4.6) and 56/65 = 86.2 (+0.0); terra 53/65 = 81.5 against 55/65 = 84.6 (+3.1) and 57/65 = 87.7 (+6.2). The pass-count change alone breaches a 10-point band on gemini, before rubric v2's R1 and R3 tighten in the opposite direction, and S4 makes a miss expensive. The threshold is therefore restated: **the new single-pass v2 clean rate must sit within 10 percentage points of the frozen run's own single-pass v1 rates, that is within 10 points of the band spanned by 39.3 and 36.1 (gemini), 90.8 and 86.2 (luna), 84.6 and 87.7 (terra).** The two-pass rate (27.9 / 86.2 / 81.5) is printed beside it as context and is never the target.

**S2c, the only genuinely human-anchored admission test available.** One-sided recall against the 65 human-confirmed FAIL rows: the new judge must label at least **60 of the 65** dirty. This is the only criterion in 2.10 whose reference is a human decision rather than an Opus pass, and it is one-sided by necessity, because no human-confirmed clean cell exists. It is applied **pooled**, against the 60-of-65 floor, and reported **descriptively per model** at 44 / 9 / 12 with no per-model floor: a floor on 9 or on 12 rows would be noise dressed as a criterion.

**S3.** Expected direction: R1 and R3 tighten the boundary, so disagreements should be predominantly clean to dirty. Every dirty-to-clean disagreement, the direction that would inflate the intervention, is individually reviewed by the human before the judge is trusted. Expected load **10 records** under the adopted calibration set of 191 rows, about 5 if the gemini block were dropped [ESTIMATE, now anchored on the measured dirty-to-clean inter-pass flips on the frozen file, gemini 5, luna 0, terra 4, that is 9 of 191 (4.7 percent) and 4 of 130, rather than on half of the two-directional rate of 21 of 191, 11.0 percent; [ASSUMPTION] that judge-versus-instrument disagreement resembles judge-versus-judge disagreement in size].

**S4.** If S2a, S2b or S2c is missed the judge is not trusted, and the pre-declared fallback is either one rubric revision followed by S1 on a held-out half with the revision reported, or abandoning the trusted-judge route and buying the comparison with human time (full two-pass plus adjudication on both comparison arms).

**The coupling the economy creates, declared here rather than discovered during the run.** Because S1 and the baseline's gating pass are one pass, the calibration gate and the baseline's gating labels are no longer independent, and that is the price of the double duty. Three consequences, all pre-declared. (1) **If S4 fires, the labels that failed the gate are also the labels the baseline column would have been scored on**, so a rubric revision invalidates both and the 18 calls and 191 labellings are spent a second time under the revised rubric; the contingency cost is about 6 to 17 USD of judge and zero human hours, and it is not a reason to weaken a threshold. (2) The calibration group is therefore judged **first**, before a single structured batch is built (Phase 5 step 14), so the second spend is avoidable in the order of operations and not merely in principle. (3) **No selection in the other direction is permitted**: the pass is re-run only because a pre-declared S2a, S2b or S2c threshold was missed, never because the baseline's resulting pass rate is inconvenient, and the realised kappa, clean-rate and recall figures are published whether the gate passes or fails.

**S1, S2a, S2b and S2c need one judge pass, not two.** The calibration compares the new judge's single pass on the 191 records against the frozen verdict. The 30 percent second-pass subsample of D1 is a separate quantity, judge-versus-judge self-consistency, comparable in kind to the 2026-09-01 run's own 0.582 / 0.775 / 0.614. Dropping that subsample would cost the self-consistency figure and nothing else; it would not weaken the calibration and would not change the gate.

### 2.11 Audit intensity, equal on every arm

Census, not sample: 100 percent of records with any negative label; 100 percent of pass disagreements where a second pass exists; 100 percent of records that **have a judgeable surface** but whose label record is missing or invalid (`judge_output_invalid`, 2.9); records with **no** judgeable surface are not audited, because 2.4 decides them deterministically and edit C2 sets `human_stage_c_required = NO` for exactly that reason (`main()` filters on `required == YES` at `:395-399`), so they never enter the audit CSV and never enter the human-decision estimate of 5.7; 100 percent of **narrative critical-event coverage** decisions where `cutoff_hours_to_cover` is non-empty (**30 per arm under the two-model design**, 3 cases x k=5 x 2 models, see 3.1). Plus a seeded random verification sample of clean records on **every comparison arm**, drawn stratified by case, seed published to `stage_c_audit_sample.json` before the auditor opens the workbook. Structured arm only: every record where the deterministic slot check and the judge's slot-claim label disagree; that trigger can only add failures to the intervention, so the asymmetry is conservative with respect to the hypothesis and is reported as such.

### 3.4 Critical-transition scoring: three reported quantities, one gate

Added by revision 5. This subsection decomposes the one pre-declared contract requirement of 3.3 into the three quantities the author has asked for: **exact-set accuracy, which remains the contract requirement and the only one of the three that enters a gate; no-omission recall, reported separately; and over-inclusion, reported separately.** The schema is **frozen** at `FINAL_ANSWER_SCHEMA_SHA256 = d079a01b22d4c344a4f2b7a6a62b147215860deeeddd373e5b597f8ed498ccf0` and no `description` string was touched after the pilot (1.2). The governance paragraph that must accompany the decomposition is printed in 3.3 above and is repeated beside the table in the thesis.

#### 3.4.1 The three metrics, defined exactly

**Ground truth, single source, unchanged.** `cutoff_events(compact)`, `scripts/validation/agent_eval.py:496-504`. It walks `compact["change_hours"]` in file order, keeps a running `prev` of the previous row's `cut_off`, and appends `row["period"]` whenever `row["cut_off"] > prev`. The first row can never be an event (`prev is None`). It returns an ordered list of integer `period` values and reads nothing else, in particular it never reads `reply`, so it is arm-independent and identical for the free baseline and the structured arm. Call this list **GT**, with `n_gt = len(GT)`.

**Emitted object, single source.** For a schema-conformant record, **EM** is `[e["period"] for e in obj["critical_transitions"]]`, in emitted order, duplicates preserved. `n_em = len(EM)`. The per-entry value `e["settlements_without_route"]` is **not** part of any of the three metrics; it belongs to the separate slot-vs-payload equality diagnostic already pre-declared in 3.3.

**Scope predicate, one for all three (`ct_scored`).** A record enters all three denominators if and only if its `contract_outcome` (taxonomy of 2.4) is `schema_invalid` with a well-formed `critical_transitions` array, `validator_invalid`, or `valid`. Records with `runtime_error`, `round_ceiling`, `contract_not_attached`, `no_final_message` or `not_json` have no array at all and are excluded, with the excluded count printed beside every published cell. A record with `status != "ok"` and three empty arrays is **in scope and scored**, not excluded: all 13 in-scope cases carry `must_call_tool=true` and the frozen fixture always succeeds, so `GT` is non-empty and such a record scores `ct_exact_set = False`, recall `0 / n_gt`, over-inclusion `0`. This is pre-declared here so nobody excludes it later as "no attempt".

**Degenerate GT.** If `n_gt == 0` the record is dropped from the recall denominator only (count printed); `ct_exact_set` and over-inclusion remain defined (`EM` must be empty).

**Metric 1, the contract requirement: `ct_exact_set` (critical-transition exact-set accuracy).**

- **Record level.** `ct_exact_set = (EM == GT)`, compared as ordered lists.
- **This is a RENAME, not a redefinition.** It is bit-for-bit the predicate already pre-declared in 3.3 as `structured_critical_event_completeness` (`[e.period for e in critical_transitions] == cutoff_events(compact)` as **ordered** lists: no missing period, no invented period, no reordering, no duplicate), which is in turn semantic rule 3 of 1.3. The schema is frozen and this predicate is frozen with it. The word "set" in the author's chosen name is shorthand; the operative test is **ordered list equality**, which is strictly stronger than set equality. That sentence must travel with the name so the name never under-sells the gate.
- **Denominator, record level:** `ct_scored` records. 65 per model, **130 per arm** under the two-model design (gpt-5.6-luna, gpt-5.6-terra, 13 cases, k=5). Excluded count printed beside the cell.
- **Event level:** not defined. Exact-set is a record-level all-or-nothing predicate by construction; any event-level figure quoted next to it belongs to metric 2 or metric 3.
- **Reconciliation identity, mandatory wherever the three are printed together.** `ct_exact_set` is True if and only if all four of these hold: no omission, no extra, no duplicate, no reordering. So `ct_exact_set` failures decompose exactly, and `ct_order_violation` and `ct_duplicate` are published as two small residual counts alongside metrics 2 and 3 so that the decomposition closes arithmetically and a reader can verify that metrics 2 and 3 account for the gate rather than approximating it.

**Metric 2, reported separately: `ct_no_omission_recall`.**

- **Event level (the primary form).** For one record, `matched = |{p in GT : p in set(EM)}|`, counted over **distinct GT periods**, so an emitted duplicate can never manufacture a second match. `recall_record = matched / n_gt`. The published figure is the **pooled** event-level recall: `sum(matched) / sum(n_gt)` over all `ct_scored` records of a model.
- **Event-level denominator.** `sum(n_gt)`. This document's own verified count is 57 cut-off events over the 13 in-scope cases (3.3, V5 paragraph), so at k=5 this is **285 events per model and 570 events per arm** under the two-model design. The figure 855 that appeared in revision 4's 3.3 is the three-model number and is corrected to 570 wherever it is carried forward. [ASSUMPTION] The 57 is carried from this document's own verified count and was not recomputed for revision 5, because recomputing it requires executing the fixture builder and nothing was run; the two cases exercised by the pilot, A03 with 8 events and B02 with 3, are independently confirmed from the pilot artefacts.
- **Record level (the secondary form).** `ct_no_omission = (set(GT) <= set(EM))`, that is `recall_record == 1.0`, True even when extras are present. Published as a rate over `ct_scored` records: 65 per model, 130 per arm.
- **The named failure it counts.** A GT period absent from `EM` is a **silent omission**: a cut-off transition present in the deterministic payload that the structured answer does not carry at all.

**Metric 3, reported separately: `ct_over_inclusion`.**

- **Event level.** `extras = multiset(EM) - multiset(GT)`, so a period emitted twice when it belongs once contributes one extra. `n_extra = |extras|`. Two published forms, both with their own denominator:
  - `ct_extra_rate_emitted = sum(n_extra) / sum(n_em)`, the share of emitted entries that do not correspond to a ground-truth transition. Denominator is the **model's own emitted total**, which is a model-dependent quantity and must be printed as a raw count beside the rate, never compared as a rate between models without both counts visible.
  - `ct_extra_per_record = sum(n_extra) / (number of ct_scored records)`, extras per record, denominator 65 per model and 130 per arm.
- **Record level.** `ct_over_inclusive = (n_extra > 0)`, published as a rate over `ct_scored` records.
- **Mandatory split, because it is the whole substance of the finding.** Every extra period is classified into exactly one of:
  - `ct_extra_in_payload`: the period exists as a `period` value in `compact["change_hours"]` but its `cut_off` did not rise there. This is **redundancy**: a real payload row copied into a list it does not belong in.
  - `ct_extra_not_in_payload`: the period does not appear in `compact["change_hours"]` at all. This is **fabrication** and is a categorically more serious finding.

  These two are never pooled into one "over-inclusion" number without the split printed beside it. On the pilot evidence every extra is `ct_extra_in_payload` and `ct_extra_not_in_payload` is zero, but zero is a result to be measured at k=5 on 13 cases, not an assumption to carry in.

**What these three do NOT measure, stated so nothing is read into them.** `settlements_without_route` correctness is the separate slot-vs-payload equality diagnostic of 3.3 (`ct_value_mismatches` in 3.4.6). A record can be exact-set correct and carry a wrong settlement count, and a record can be over-inclusive while every value it emitted is payload-exact. On the four pilot records all 28 emitted `settlements_without_route` values equal the payload `cut_off` at that period, including all six of luna's over-included entries, which is precisely why the pilot's error is classifiable as redundancy rather than fabrication.

#### 3.4.2 Which metric enters which gate

**`ct_exact_set` is a contract term and enters exactly one gate.**

It is semantic rule 3 of 1.3 (`critical_transitions` reproduces every `change_hours` row with `cut_off` rising, in order, none missing, none invented). Its failure sets `contract_outcome = validator_invalid` (outcome 7 of the 2.4 taxonomy). It therefore enters:

- `contract_validity_rate` (3.3), as a failure;
- **SSP, the complete structured-system pass**, through the composition already written in 3.1: `SSP = C5-common AND contract_outcome == "valid"`;
- and nothing else.

It does **not** enter `json_schema_validity_rate`, because a superset array is perfectly schema-conformant; that separation is the point of publishing the two rates rather than one.

**The one sentence a reader cannot misread, to be printed wherever the metric appears:**

> Exact-set accuracy scores a JSON array that only one arm is able to emit at all, so putting it into the common Stage-C comparison would score the free-text baseline zero on a field it was never asked for and could not have produced; it therefore lives in the complete structured-system pass (SSP), which is intervention-only, and never in C5-common, which is the arm-to-arm comparison.

C5-common already carries the standing rule from 2.4, restated here because this metric is the one most likely to be smuggled in: **C5-common contains no schema term of any kind.** A record can fail `ct_exact_set`, fail SSP, and still PASS C5-common on the strength of its Greek narration. That is deliberate and is what keeps the comparison fair.

**`ct_no_omission_recall` and `ct_over_inclusion` enter no gate whatsoever.** Not C5-common, not SSP, not either validity rate, not `full_system` in `scripts/validation/axis3_full_system.py`. No `ct_*` field may be added to the `components` tuple at `axis3_full_system.py:211-218`; that tuple stays `(det, stage_c, coverage)` exactly as it is today.

#### 3.4.4 The asymmetry argument, written for the thesis

**Why omission is the dangerous failure mode.** The four slots of the contract are not four equally weighted facts; they are the skeleton of an evacuation timeline. A `critical_transitions` entry is the hour at which the count of settlements with no remaining escape route rises, which in operational terms is the hour at which some settlement stops being reachable by road. If that entry is missing from the answer, the loss of access at that hour is never narrated to anyone: the decision maker reads a timeline that is internally coherent, carries no gap and no warning, and is silently short one transition. The failure is invisible at the point of use, which is the property that makes it dangerous, and it is the same failure the free-text baseline's `cover_cutoff_events` policy and the Result-Ignore red flag at `scripts/validation/agent_eval.py:1058-1064` were written to catch. Over-inclusion of a real payload row is a different object. The added row is a genuine `change_hours` record with its own genuine `cut_off` value, carried into a list where the value did not rise. The reader is given an hour at which the situation did not worsen, presented among hours at which it did. That is redundancy and imprecision, and it costs attention and clarity, but it invents nothing, hides nothing, and every number in it is traceable to the tool output. In an evacuation decision-support setting the two are not symmetric, and a reporting scheme that collapsed them into one error count would be claiming they are.

**The counter-argument, stated honestly and not softened.** The contract does not say "do not omit". Its exact words, frozen in the schema at `scripts/validation/wfeds_final_answer_schema.json`, are that every qualifying row must appear "και καμία άλλη γραμμή δεν επιτρέπεται να προστεθεί", no other row may be added. A model that adds rows has not followed the instruction it was given. This experiment's entire subject is the LLM/tool interface and whether an explicitly described machine-readable contract is obeyed; over-inclusion is a direct, unambiguous, measured instruction-following failure of exactly the kind the experiment exists to detect. Reporting recall alone would let a model that copied the whole `change_hours` table into `critical_transitions` score a perfect 1.000 on the headline decomposition figure, which is the reductio: a model that ignored the filter entirely would look flawless. Worse, it would understate the intervention's own weakness, because the whole promise of the structured contract is that it moves a narration problem into a field the provider enforces, and here is a case where constrained decoding enforced the shape and did not enforce the rule stated in the field's own description. That is the single most informative negative result available from this design, and recall-only reporting would erase it.

**Why reporting all three is the honest resolution.** The three metrics answer three different questions and none of them substitutes for another. `ct_exact_set` answers "was the contract met", and it stays the gate, unchanged, unweakened, and inside SSP. `ct_no_omission_recall` answers "did the answer lose a transition that the payload contained", which is the operational safety question and the one a fire service would ask. `ct_over_inclusion`, split into in-payload redundancy and not-in-payload fabrication, answers "in what way did the contract fail", which is the instruction-following question and the one a thesis examiner would ask. Publishing only the gate would say a model failed without saying how, and would put "added two redundant rows" and "dropped a settlement's cut-off hour" behind the same word FAIL. Publishing only recall would hide a real contract violation behind a perfect score. Publishing all three, with the gate unchanged and the other two explicitly barred from every pass rate, is the only arrangement in which both questions get an answer and neither answer is allowed to stand in for the other.
